相机 APP — 需求汇总

布局结构

顶栏 52px← 返回(左，自定义图标) + 功能名(居中)
预览区相机画面填充
底栏 52px🖼 图库(左) + ⭕ 快门(中) + ⚙ 模式(右)

交互逻辑（3 种状态）

📷 拍照模式

  • 快门白圈，模式图标白色
  • 按下快门 → 拍照存 /data/photo/
  • 蜂鸣反馈

🎬 录像待机

  • 模式图标变绿色
  • 快门变红色圆
  • 按下开始录制

🔴 录像中

  • 快门变红色方块
  • 预览区顶部居中显示录制时间
  • 按下停止录制 → 存 /data/photo/

图库（二级页面）

  • 按下图库按钮 → 进入图库页面
  • 顶栏同上（返回 + 居中标题）
  • 扫描 /data/photo/ 所有照片，按日期排列
  • 点击返回 → 回到相机预览

下面是实现这个需求的 2 种技术方案：

A

LVGL 全程运行（推荐）

不调 lv.deinit()，Sensor → VIDEO1 层，LVGL → UI 层叠加。顶栏+底栏是 LVGL 对象，预览区透明露出相机画面。
优点：满帧 UI，按钮即时响应，图库/相机切换流畅
风险：需验证 K230 双层显示是否稳定

B

LVGL / Camera 互斥（保守）

拍照或进图库时关闭相机→恢复 LVGL→完成操作→重新开相机。与当前架构一致。
优点：无技术风险
缺点：每次模式切换黑屏 0.5-1s，录像时无法显示计时器
